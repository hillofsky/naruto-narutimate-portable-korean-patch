# 개발 도구 검증 — 2026-10-16

## 실행 환경과 격리

Windows / Python 3.9.7에서 실행했다. 새 도구와 의존 소스/데이터를 별도 폴더로 복사하고, 저장소 루트가 아닌 작업 디렉터리에서 실행했다. 역사적 작업 폴더는 기준 ISO를 읽는 입력 경로로만 제공했다. 새 도구는 과거 개발 디렉터리의 스크립트나 이미지에 접근하지 않는다. Linux/macOS 실환경 검증은 NOT_RUN이다.

## 실제 기준과 결과

입력 SUB52U의 SHA-256을 patch/sub52/manifest.json과 대조해 통과했다.

- CCS 추출/변경 없는 재빌드 PASS. 결과 SHA-256 `3192c66bf22f2a21b03346e6549f3c6d01f1d7ac69ec91c645ff7ed6fb503e5f`로 기준 ISO와 바이트가 일치했다.
- TEX_xgauge5의 한 픽셀만 바꾼 합성 CCS를 이용해 실제 변경 경로를 검사했다. 이는 번역 결과물이 아닌 테스트 입력이다.
- 최초 append 방식은 4GiB 제한에서 정상 중단했다. 안전한 기존 슬롯 재사용을 추가한 뒤 별도 폴더에서 빌드/primary와 FSTS 재삽입/비대상 primary 및 FSTS 바이트/모든 비대상 ISO 활성 파일 비교 PASS.
- 부족한 디스크 공간 오류도 관찰했다. 전용 임시 폴더를 정리하고, 이후 사전 여유 공간 검사를 추가했다. 사용자 원본/기존 빌드 파일은 삭제하지 않았다.
- 기존 출력 경로 재사용 및 틀린 기준 ISO 입력 거부 PASS.
- 독립된 새 후보이며 기존 manifest나 배포물을 갱신하지 않았다. 합성 ISO는 검사 후 삭제했다.

릴리즈 xdelta 재다운로드/원본 ISO에서의 재적용, PPSSPP 실행, 실제 화면, PSP 실기, 전체 플레이는 NOT_RUN이다. 새 후보 runtime_qa는 PENDING이다. 코드의 정적 보존 검증을 화면 정확성이나 번역 완성도로 해석하지 않는다.
